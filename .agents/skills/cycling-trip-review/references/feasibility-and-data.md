# 成立性とデータ整合性の監査

## 日別の成立性

各日を時間順にたどり、次を同時に満たすか確認する。

- すべてのハード制約と、変更していない予約済み項目
- 出発可能時刻、区間ごとの所要時間、最終受付、チェックイン締切、日没
- 距離、標高、路面、交通量と旅行者の体力・経験
- 輪行の受付、準備、待ち、乗換、積み降ろし、持込条件
- 食事、補給、入浴、荷物の受渡し
- 天候悪化や遅延時に削れる任意項目と撤退手段

時間窓の端への到着は成立扱いにしない。候補時間、到着目標、余裕、中止条件を分ける。

## 泊まりと日付の連続性

前日の終着地と翌日の出発地、宿泊地域、翌朝最初の体験を照合する。最終日は帰着期限までの全移動を含める。宿候補が少ない地域は、在庫未確認のまま確定泊として扱わない。

## 根拠品質

旅行日に有効な一次情報があるか、変動する事実に確認日と再確認要否があるかを確認する。空室、運行、通行可否を、検索結果がないことや古い情報から断定しない。

## 機械検証と人の判断を分ける

次は `.venv/bin/python tools/validate.py` で確認する。

- JSON Schema適合
- 重複ID
- 安定IDと参照の整合性
- 日付順と日付範囲
- 前日終点と翌日始点
- 閉じたIssueの解決記録
- 距離の単調増加と表示値の重複
- 宿泊候補と現行宿泊地域の整合性

検証成功は、時刻表の正しさや体験価値を保証しない。生成物を更新する場合は `tools/render.py` を実行し、差分で確定・推奨・任意・未確認・当日判断の表現も確認する。

推定値は精度を誇張せず、幅、確信度、計算方法を示す。レビュー結果には、旅行者が次に決めることと確認することを残す。
