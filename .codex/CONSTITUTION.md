# Codex 憲法

## ChatGPT への調査依頼プロンプト

### 0. 強制ルーティング

次のいずれかを作成・更新・移動しようとした時点で、この規則を適用する: ChatGPTに送る命令本文、ChatGPTが読む自己完結資料、ChatGPTに添付するファイルまたはアーカイブ。

| 判定 | 操作 |
| --- | --- |
| ChatGPTにそのまま渡す内容 | `.codex/local/chatgpt-research/<request-id>/` だけに置く。`<request-id>` は依頼単位で一意にする。 |
| ChatGPTに渡さない恒久的な運用仕様 | 追跡してよい。ただし、ChatGPTへの命令文、添付前提、貼り付け案内を含めない。 |
| 上のどちらかを判定できない | ファイル作成、既存ファイルの更新、追跡領域への移動を停止する。ユーザーの判断が得られるまで代替保存先を選ばない。 |

`prompts/` は廃止済みの配置であり、ChatGPT調査ブリッジを置く例外はない。再利用可能に見える依頼文、既存Issue専用の依頼文、Google Maps確認依頼も例外ではない。

### 1. 作成前・作成後の停止条件

ブリッジを作るときは、本文を書き始める前に次を順番に満たさなければならない。

1. `python3 tools/chatgpt_research.py init <request-id>` が成功し、依頼単位のディレクトリが作成されている。
2. 作成対象がそのディレクトリ配下の `.md`、または同一依頼の添付ファイルである。
3. `python3 tools/chatgpt_research.py preflight <対象パス>` が成功している。

この3つのどれかに失敗したら、本文の作成、ファイルの移動、ユーザーへの「完成」報告を停止する。パスを変えて再試行してはならず、許可された依頼ディレクトリを初期化するか、判定不能としてユーザーに確認する。

ChatGPTへ渡す本文は、ユーザーがそのままペーストできる本文だけで構成する。作成者向け説明、貼り付け方の案内、ローカルパスだけを示すメタ情報、前置きは含めない。

### 2. 完了時のガベージコレクション

回答を受領した、依頼を取りやめた、または依頼内容を置き換えた時点で、まず必要な恒久データだけを正本へ反映する。その後、`python3 tools/chatgpt_research.py gc <request-id>` を実行して、当該依頼のプロンプト・引き渡し資料・添付アーカイブを依頼単位で削除する。

GCコマンドが拒否した場合は削除を停止する。未完了の依頼、他の依頼で参照中の資料、またはユーザーが保存を明示した資料はGCしない。完了報告では、GCした依頼IDを簡潔に併記する。

恒久的に残すのは、回答から反映した正本データ、再現性のために必要な調査記録、およびChatGPTへそのまま渡す内容ではない運用仕様だけである。
