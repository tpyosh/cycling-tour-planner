# 宿泊先への電話確認リスト

対象は大人1名・1室・個室、自転車1台です。予約操作や電話発信はまだ行っていません。各宿へ電話したら、結果を `research/lodging.yaml` の該当する `phone_check.result` に記録し、`phone_check.status` を `completed` に変更します。

## 判定ルール

- `web_available`: 指定日・大人1名・1室のWeb在庫を確認済み。通常の予約候補とし、自転車保管だけ未確認なら電話してよい
- `explicit_web_unavailable`: 宿が実際に利用する公式予約システムまたは信頼できるOTAで、指定日の大人1名・1室が満室または販売終了と明示されている
- `phone_required`: 公式が電話予約のみ、日別空室を確認できるWeb予約システムがない、またはOTA在庫が公式販売在庫と連動する根拠がない
- `single_occupancy_phone_check`: 部屋は販売されているが、Webでは2名利用しか確認できず、1名利用不可または1名1室満室とは明示されていない
- Web在庫を適切に観測できる宿はWebで判定する
- Web満室が明示された宿は、裏在庫への期待だけを理由に電話しない
- OTAで料金が出ない、検索結果に出ない、プランが表示されないというだけでは満室と判定しない
- 電話予約主体の小規模宿はWeb上の在庫なしと解釈せず、電話確認する
- 小規模地域ではWeb検索だけで地域全体の宿泊可能性を判断しない
- 電話前のavailabilityは推測せず、availability_unknownのままにする

## Web満室として電話対象から除外する宿

既存リポジトリには、指定日の大人1名・1室について明示的なWeb満室を記録した宿泊候補はありません。今後該当する宿を確認した場合は、根拠URLと確認日を `research/lodging.yaml` の `explicit_web_unavailable` に追記し、電話候補へ戻しません。

## 9/26 登別の扱い

- 登別温泉の主要宿はオンライン販売が成熟しているため、既存Web調査を基本的に信用する
- 価格または1名利用条件が合わなければ、stay.noboribetsuまたはstay.higashi-muroranのWeb予約可能なビジネスホテルを優先する
- Web満室の大規模旅館へ裏在庫を期待して順番に電話しない
- 公式が電話予約主体の小規模宿を新たに確認した場合だけ電話候補へ追加する
